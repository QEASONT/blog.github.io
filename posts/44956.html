Hadoop-2.6.5 && Zookeeper && Spark-2.2.0 高可用集群配置

Spark Hadoop 集群部署
数据处理 Hadoop
发布日期:   2024-06-19
文章字数:   3k
阅读时长:   16 分
阅读次数:  

写在前面

每次有段时间不配集群就会忘记具体的操作步骤，然后又会耗费大量的时间重新找教程-看文档-debug，非常折磨。希望通过这篇文章详细地记录配置高可用集群的过程，为有需要的朋友和未来的自己节省时间。

前置要求

项目涉及的软件包和版本信息要求如下：

Scala==2.12.15
Java==1.8
Hadoop==2.6.5
Spark==2.2.0
Zookeeper==3.4.6

将所有的软件包下载并放置到指定位置，设置好环境变量，包括.bash_profile和.bashrc等文件。

Zookeeper配置

修改Zookeeper路径中conf/zoo.cfg配置文件，内容如下：

tickTime=2000
initLimit=10
syncLimit=5
dataDir=/home/qt/opt/module/zookeeper-3.4.6/tmp
dataLogDir=/home/qt/opt/module/zookeeper-3.4.6/log
server.1=0.0.0.0:2888:3888
server.2=xxxx.11:2888:3888
server.3=xxxx.12:2888:3888
clientPort=2181

注意，有时会出现奇妙的问题，可以考虑把本机的ip改成0.0.0.0。

在你设置的dataDir路径下，创建myid文件，server.1中的myid文件内容为1，以此类推，不要包含额外的空格或是换行符。

在三个机子上分别使用~/opt/module/zookeeper-3.4.6/bin/zkServer.sh start命令启动Zookeeper，可以使用~/opt/module/zookeeper-3.4.6/bin/zkServer.sh status查看启动情况。

Hadoop配置

修改Hadoop路径中etc/conf/hdfs-site文件，内容如下：

<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="configuration.xsl"?>
<configuration>
<!--执行hdfs的nameservice为ns,和core-site.xml保持一致-->
<property>
<name>dfs.nameservices</name>
<value>ns</value>
</property>
<!--ns下有两个namenode,分别是nn1,nn2-->
<property>
<name>dfs.ha.namenodes.ns</name>
<value>nn1,nn2</value>
</property>
<!--nn1的RPC通信地址-->
<property>
<name>dfs.namenode.rpc-address.ns.nn1</name>
<value>node10:9000</value>
</property>
<!--nn1的http通信地址-->
<property>
<name>dfs.namenode.http-address.ns.nn1</name>
<value>node10:50070</value>
</property>
<!--nn2的RPC通信地址-->
<property>
<name>dfs.namenode.rpc-address.ns.nn2</name>
<value>node11:9000</value>
</property>
<!--nn2的http通信地址-->
<property>
<name>dfs.namenode.http-address.ns.nn2</name>
<value>node11:50070</value>
</property>
<!--指定namenode的元数据在JournalNode上的存放位置,这样，namenode2可以从jn集群里获取
          最新的namenode的信息，达到热备的效果-->
<property>
<name>dfs.namenode.shared.edits.dir</name>
<value>qjournal://node13:8485;node14:8485;node15:8485/ns</value>
</property>
<!--指定JournalNode存放数据的位置-->
<property>
<name>dfs.journalnode.edits.dir</name>
<value>/home/qt/opt/module/hadoop-2.6.5/journal</value>
</property>
<!--开启namenode故障时自动切换-->
<property>
  <name>dfs.datanode.max.transfer.threads</name>
  <value>8192</value>
</property>
<property>
<name>dfs.ha.automatic-failover.enabled</name>
<value>true</value>
</property>
<!--配置切换的实现方式-->
<property>
<name>dfs.client.failover.proxy.provider.ns</name>
<value>org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider</value>
</property>
<!--配置隔离机制-->
<property>
<name>dfs.ha.fencing.methods</name>
<value>sshfence</value>
</property>
<!--配置隔离机制的ssh登录秘钥所在的位置-->
<property>
<name>dfs.ha.fencing.ssh.private-key-files</name>
<value>/home/qt/.ssh/id_rsa</value>
</property>
<!--配置namenode数据存放的位置,可以不配置，如果不配置，默认用的是core-site.xml里配置的hadoop.tmp.dir的路径-->
<property>
<name>dfs.namenode.name.dir</name>
<value>file:///home/qt/opt/module/hadoop-2.6.5/tmp/namenode</value>
</property>
<!--配置datanode数据存放的位置,可以不配置，如果不配置，默认用的是core-site.xml里配置的hadoop.tmp.dir的路径-->
<property>
<name>dfs.datanode.data.dir</name>
<value>file:///home/qt/opt/module/hadoop-2.6.5/tmp/datanode</value>
</property>
<!--配置block副本数量-->
<property>
<name>dfs.replication</name>
<value>3</value>
</property>
<!--设置hdfs的操作权限，false表示任何用户都可以在hdfs上操作文件-->
<property>
<name>dfs.permissions</name>
<value>false</value>
</property>
<!--no datanode 报错-->
<property>
        <name>dfs.client.block.write.replace-datanode-on-failure.enable</name>     
         <value>true</value>
    </property>
    <property>
    <name>dfs.client.block.write.replace-datanode-on-failure.policy</name>
        <value>NEVER</value>
    </property>
</configuration>

修改slaves文件，填入节点的ip。

完成以上配置文件后，在你设置的<name>dfs.namenode.name.dir</name>路径下创建好文件夹，再在配置的Journal Node节点上（有多个的话每个都要启动）通过以下命令启动Journal Node：

/home/qt/opt/module/hadoop-2.6.5/sbin/hadoop-daemon.sh start journalnode

完成后在主节点上使用hadoop namenode -format命令对namenode进行格式化。

格式化后有可能遇到nn1和nn2切换的问题，出现报错

Unexpected error occurred  Call From node10/10.214.151.10 to node11:9000 failed on connection exception: java.net.ConnectException: Connection refused;

使用如下命令切换nn的Activate状态：

hdfs haadmin -transitionToActive --forcemanual nn1 --forceactive

注意，这个--forceactive很重要。

完成配置之后，通过这个命令可以群起脚本：

~/opt/module/hadoop-2.6.5/sbin/start-dfs.sh && ~/opt/module/hadoop-2.6.5/sbin/start-yarn.sh && ~/opt/module/hadoop-2.6.5/sbin/mr-jobhistory-daemon.sh start historyserver && ~/opt/module/spark-2.2.0-bin-qt/sbin/start-all.sh
